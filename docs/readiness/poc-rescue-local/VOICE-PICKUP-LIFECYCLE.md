# Voice finalization when the caller leaves before pickup

October 5, 2026. This is a local lifecycle repair; it makes no provider-registration, call-delivery or audibility claim.

The controlled live call rejected at the SIP carrier boundary exposed a separate application race. The first-participant callback waited for an outbound `sip.callStatus=active` before calling `SessionRecorder.start()`. A participant departure during that wait entered artifact finalization while the recorder had never acknowledged a session row. Each attempt returned false, even when the dispatcher had already created the canonical conversation. The pending pickup callback could also resume after its deadline and initialize a greeting after teardown.

The regression executes the actual `run_bot` callbacks with a deterministic transport and mocked external voice processors. It retains the real `SessionRecorder`, transcript writer and local artifact store. Before the fix, the early-departure scenario reproduced six canonical-finalization error messages, no session-finalize call, and a pickup handler still waiting after participant departure. It does not rely on source-string assertions or mark an unsuccessful persistence operation as successful.

The recorder now creates or acknowledges the existing session before running the pipeline, independently of pickup. The existing client behavior for a dispatcher-created session remains unchanged. A creation exception prevents pipeline startup and caller readiness. Audio capture, the talk clock and usage reporting still begin only after the existing pickup gate; the carrier-without-status timeout behavior is preserved. An outbound attempt starts with `answered=false`, changes only after observed pickup, and remains zero talk seconds if disconnected while ringing. Inbound answer semantics remain unchanged.

A call-local closing event is set before finalization I/O and shutdown announcements. Pickup wakes immediately on this event. Startup checks the same event after asynchronous setup, before flow initialization and before scheduling a model warmup or duration task. Departure after pickup retains the truthful answered result while preventing a late greeting when setup has not completed.

Verification: `voice-pickup-lifecycle.log` in `.artifacts/poc-rescue-local/` records **61 passed, zero failed** across the targeted bot pickup, answer waiting, recorder finalization, readiness, run-call, observer and runtime-failure suites. Cases cover early departure, normal pickup, missing carrier attributes, unchanged inbound behavior, departure during recording setup, room-finished cancellation, departure during flow initialization, and session-creation failure. Ruff passes for all four changed source/test files; pyrefly reports zero errors with one existing suppression in the selected runtime sources. No real providers were invoked. A rebuilt/deployed image and a separate controlled live call remain the deployment owner's acceptance steps.
