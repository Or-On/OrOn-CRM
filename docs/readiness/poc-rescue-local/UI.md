# Local UI verification — 2026-10-04

## Scope and provenance

The original checkout was `3582027b`; its before screenshots are retained, but it was not the deployed source. The current pass uses merge `635d245` (includes deployed `origin/main` `42eebac2`) plus the scoped UI changes recorded by the following UI commit. Original local changes were preserved in `86c3641` before merging. Existing upstream template credential isolation, media rendering, opening-menu visibility, permissions, and exact microsecond ticket cursor were retained.

The browser ran the real Next application at localhost:3100 against a newly migrated, owned `oron_ui_preview_*` PostgreSQL database, created by `scripts/preview_ui.py --browser-login`. The fixture owner used **Or-On Fictional Preview** and **ProTouch Fictional QA**. These are synthetic tenants and do not establish behavior of the real customer accounts. The original developer database and `.env` were not seeded or replaced. Messaging and voice provider workers were disabled. The preview contains 540 additional fictional contacts and 55 tickets, inserted by `.artifacts/poc_rescue_ui_seed.py` only after validating the owned preview database name.

Responsive DOM measurements cover 29 additional route instances plus Inbox and ticket list: 31 distinct routes/states at widths **320, 375, 390, 430, 768, 1366, 1920**. No document horizontal overflow was measured. Four of those are denied states, not proof of their authorized content. This does not prove every control fits, every nested table is usable, or that every route works in every role. Ticket list LTR and Inbox RTL were inspected with mixed Hebrew/English text, phone numbers and dates. Many additional routes were inspected in both desktop English and mobile Hebrew.
